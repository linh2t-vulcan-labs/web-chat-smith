# @cs/icons

Turns a raw Figma icon export into React components at `@cs/icons/<slug>`, consumed by `@cs/ui` and every app in the monorepo.

## Usage

```tsx
import { IconChevronLeft } from "@cs/icons/chevron-left";

<IconChevronLeft size={20} className="text-muted-foreground" />;
```

- Import each icon from its own subpath (not a barrel) for tree-shaking.
- Directional icons (`chevron-left`, `corner-down-right`, ...) auto-flip under `dir="rtl"` via a baked-in `rtl:` class — nothing to do at the call site.
- `@cs/icons/latest/<slug>` and `@cs/icons/icons_v1/<slug>` also work, for pinning to a specific version after `.current` moves on.

## How it works

```
figma-icons/icons_v1/          source dump, committed to git
  icons/, graphics/, ...       one folder per category (any name works)
  names.json                   human-filled names for shapes Figma didn't name
  _preview.html                visual review of every shape, generated by `preview`/`gen`
  .current                     which version is active

generated-icons/               build output — do not hand-edit
  icons_v1/icons/*.tsx
  icons_v1/graphics/*.tsx
  index.ts, types.ts           shared, hand-authored
```

A shape resolves to a slug from its own filename if that's already meaningful (`chevron-left.svg`), or from a `names.json` entry (for placeholders like `meaning-42.svg`). Two shapes resolving to the same slug — even across categories — show up as a **duplicate**; give one a different name in `names.json`.

## CLI

```bash
bun run gen                      # from packages/icons — resolves .current, writes generated-icons/**
bun run icons <command> [args]   # from packages/icons — or `bun run gen icons <command>` from repo root
```

| Command | What it does |
| --- | --- |
| `audit [version\|--all]` | Resolved / duplicate / unresolved counts. Read-only. |
| `preview [version]` | Writes `_preview.html` + the `names.json` stub. Read-only otherwise. Defaults to `.current`. |
| `version init <icons_vX>` | Create an empty folder for a new Figma export. |
| `version use <icons_vX>` | Switch `.current` and sync `package.json` exports. |
| `diff [prev] [next]` | Diff which slugs two versions resolve to. |

### New Figma export

1. `bun run icons version init icons_v2`
2. Unzip each category into `figma-icons/icons_v2/<category>/`
3. `bun run icons preview icons_v2` — open `_preview.html`, fill in `names.json` for anything unresolved or duplicate, repeat until it looks right
4. `bun run icons version use icons_v2`
5. `bun run gen`

## Notes

- `scripts/lib/svg.ts` parses `<path>`, `<circle>`, `<rect>`, `<ellipse>`, `<g>`, `<mask>`, `<defs>`, `<linearGradient>`, `<stop>`. A shape using anything else (`<pattern>`/`<use>`/embedded raster images) is named but shows up under "Named, but couldn't parse" in `_preview.html` instead of generating — extend `svg.ts` if that's a real icon and not one-off junk.
- `scripts/commands/` is thin (arg parsing, console output); `scripts/lib/` has the actual logic.
